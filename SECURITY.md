# Security Policy

## Supported Releases

We actively maintain and provide security patches for the current major release of each public repository under `@isihussain`.

| Version / Target | Supported |
|---|---|
| Latest default branch (`main`) | :white_check_mark: Yes |
| Latest tagged release (`vX.Y.Z`) | :white_check_mark: Yes |
| Historical branches / older releases | :x: No |

---

## Reporting a Vulnerability

If you discover a security vulnerability or suspect an exploitable flaw in any codebase, do not open a public issue or discussion.

1. **GitHub Private Vulnerability Reporting**:
   - Navigate to the repository's **Security** tab.
   - Click **Report a vulnerability** to open an encrypted advisory draft.
2. **Direct Security Contact**:
   - For sensitive disclosures across all repositories, submit reports via GitHub Security Advisories.

---

## Disclosure Guidelines

- Include detailed reproduction steps, proof-of-concept scripts or payloads, and environment specifications.
- Allow 48 hours for initial triage and verification.
- Coordinated public disclosure occurs only after an official patch or advisory release is published.
